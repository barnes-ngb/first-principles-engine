# UX AUDIT 2026-08 — the parent-facing paper cuts

**Run date:** 2026-08-17 · **Baseline:** `origin/main` @ `212a928` · **Branch:** `claude/ux-audit-2026-08-4ieerz`

**Why this audit exists.** Owner direction (Nathan, 2026-08-17): *"this boilerplate that just has a deluge of videos seemed like a poor starting setup… it's UI things like this that make me wish you did a better job."* The cause is structural: ~50 runs of defect fixes and feature slices, every review aimed at data safety and honesty, and no run has ever owned UI coherence as its job. This run creates that discipline, modeled on the monthly architecture audit: **walk, file, rank — fix nothing**, with one narrow exception (pure label-text corrections where the current word is dishonest about the data model; each applied fix is listed in §0 and the PR body).

**Method.** The app cannot be run from this environment; the audit walks what the code says the screen shows — the parent-facing JSX, surface by surface: copy, labels, chips, empty states, section order, card hierarchy, dead ends. Kid-mode surfaces got a read-only pass (flag, never touch). Every surface was asked five questions, in order:

1. **Label honesty** — does every control say what it does in the data model's own truth?
2. **First-glance hierarchy** — what does the screen lead with, and is that what the parent came for?
3. **Consistency** — same concept, same words, everywhere.
4. **Dead ends and forced detours** — flows that strand the parent, or force a screen visit for a one-tap act.
5. **Absurd states** — computed copy that can say something ridiculous.

**Severity.** **P1** = confusing-or-dishonest (a control or copy that misleads about what happened / what a tap does, or a state that hard-blocks a family member with no recourse). **P2** = inconsistent (same concept, different words/behavior). **P3** = polish. P1s get individual ledger rows; this doc carries everything.

**A note on the drafting gap.** The run prompt was drafted in the FEAT-149 era; FEAT-139 (merged 2026-08-11) had already fixed part of the Watch Library indictment — the card deluge now has search/filter/subject grouping, an Archive tab with "Put back", and windowed history wording with an honest loading/failure guard. What survived of the original indictment is filed below (UX-01–UX-04); what FEAT-139 fixed is credited in §8.

## 0. The one exception: fixes applied in this run

Per the run's rails, only **pure label-text corrections where the current word is dishonest about the data model** were applied. One family qualified:

- **UX-01 (applied).** Watch Library "Remove" → "Archive". The write is a status flip to `'retired'` — nothing is deleted, and the surface's own vocabulary is already Archive + "Put back" — yet the row button said **"Remove"**, the confirm button **"Remove from library"**, and three explainer/empty-state strings said "removed". Changed: row button → `Archive` (`WatchVideoCard.tsx:164`), confirm button → `Move to Archive` (`:139`), confirm question → `Move "{title}" to the Archive? … You can put it back anytime.` (`:129`), plus the three "removed from the library" strings in `WatchLibraryTab.tsx` (`:211`, `:232`, `:244`) → "archived"/"are in the Archive". Text-only; test selectors updated to the new accessible names.

Candidate siblings examined and **not** fixed here, because the dishonesty is in behavior, not the word: `CurriculumTab`'s "Remove" (UX-48 — it really does remove, permanently and without confirm; the fix is a confirm, not a synonym) and Today's "Remove from today" (honest — it removes the row). Kid-surface labels ("Save Capture", UX-74) are filed, not touched, per the read-only rail.

## 7. Cross-cutting patterns (why this keeps happening)

1. **The verb doesn't match the write.** Remove-that-retires (UX-01), Remove-that-deletes-unconfirmed (UX-48), Review-that-writes (UX-32), Save-that-logs-minutes (UX-74), Refresh-that-regenerates (UX-57), Not-this-that-destroys (UX-35). One review question would catch all of these: *trace the onClick, then read the button aloud.*
2. **Fallbacks written for the compiler, not the sentence.** `?? 'this week'` (UX-34), `?? 'Unknown'` (UX-60), `?? ''` inside quotes (UX-60), `'Someone'` (UX-27). Every fallback string should be read in the sentence it lands in.
3. **Computed copy with no zero/singular/time guard.** Est. finish (UX-07), "0 answered" celebration (UX-11), "1 lessons/blocks/words/spaces" (UX-46/60/71/27), "Just these 1!" (UX-81), "0 to discover..." (UX-81), green `0m/150m` (UX-71).
4. **State cleared or kept in the wrong places.** Pending cards wiped by the next message but stale across tab switches (UX-33); attachments kept across tabs (UX-43); teach-back unmounted on save (UX-20); planner edits rebuilt away (UX-61).
5. **The confirmation budget is spent on the wrong actions.** Reversible acts confirm (Skip a chapter, Publish); destructive acts don't (delete a workbook, Unpublish, revert a narrative, remove a row) — UX-16/48/54/57/58.
6. **Ethos wording exists and then isn't used.** The no-shame `cause` line is authored and discarded (UX-51); `EmptyState` documents the convention its callers break (UX-24); "Struggling" ships beside a "No grades" strip (UX-49).
