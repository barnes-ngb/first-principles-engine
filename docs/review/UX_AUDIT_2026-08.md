# UX AUDIT 2026-08 — the parent-facing paper cuts

**Run date:** 2026-08-17 · **Baseline:** `origin/main` @ `212a928` · **Branch:** `claude/ux-audit-2026-08-4ieerz`

**Why this audit exists.** Owner direction (Nathan, 2026-08-17): *"this boilerplate that just has a deluge of videos seemed like a poor starting setup… it's UI things like this that make me wish you did a better job."* The cause is structural: ~50 runs of defect fixes and feature slices, every review aimed at data safety and honesty, and no run has ever owned UI coherence as its job. This run creates that discipline, modeled on the monthly architecture audit: **walk, file, rank — fix nothing**, with one narrow exception (pure label-text corrections where the current word is dishonest about the data model; each applied fix is listed in §0 and the PR body).

**Method.** The app cannot be run from this environment; the audit walks what the code says the screen shows — the parent-facing JSX, surface by surface: copy, labels, chips, empty states, section order, card hierarchy, dead ends. Kid-mode surfaces got a read-only pass (flag, never touch). Every surface was asked five questions, in order:

1. **Label honesty** — does every control say what it does in the data model's own truth?
2. **First-glance hierarchy** — what does the screen lead with, and is that what the parent came for?
3. **Consistency** — same concept, same words, everywhere.
4. **Dead ends and forced detours** — flows that strand the parent, or force a screen visit for a one-tap act.
5. **Absurd states** — computed copy that can say something ridiculous.

**Severity.** **P1** = confusing-or-dishonest (a control or copy that misleads about what happened / what a tap does, or a state that hard-blocks a family member with no recourse). **P2** = inconsistent (same concept, different words/behavior). **P3** = polish. P1s get individual ledger rows; this doc carries everything.

**A note on the drafting gap.** The run prompt was drafted in the FEAT-149 era; FEAT-139 (merged 2026-08-11) had already fixed part of the Watch Library indictment — the card deluge now has search/filter/subject grouping, an Archive tab with "Put back", and windowed history wording with an honest loading/failure guard. What survived of the original indictment is filed below (UX-01–UX-04); what FEAT-139 fixed is credited in §8.

## 0. The one exception: fixes applied in this run

Per the run's rails, only **pure label-text corrections where the current word is dishonest about the data model** were applied. One family qualified:

So an active tag or child filter hands `DrawingGroupCard` a *subset* of the drawing, and the card believes that subset is the whole group: the chip reads `{n} versions` of the visible slice, and "Delete this drawing?" promises to remove "all {n} of its versions" while `handleConfirmDelete` deletes only the ones on screen. The **rename** path was fixed in FEAT-160 (it now receives the unfiltered group via `allVersions` and writes it in one batch); the count and the group delete were deliberately **not** widened into that change and are filed here. *Fix:* group from the full sticker list and filter which versions *render*, so the card always knows the drawing it is showing part of — then the count, the delete copy and the delete itself are all honest at once.

- **UX-100 · P2 — the Book Editor is the *next* uncapped kid-facing image generator (filed by FEAT-166's call-site sweep, not fixed).** FEAT-166 enumerated every client `enhanceSketch(` / `generateImage(` call site rather than trusting a hand-written list — the exact failure mode that left UX-95's fourth door open. On the Stickers surface the answer is clean: four doors, four caps. But the sweep found **four more paid generators on the Book Editor surface**, all reachable by a kid making a book and none of them capped: `BookEditorPage.tsx:774` (page illustration), `useBookIllustrator.ts:78` (illustrate-the-whole-book, which spends **one call per page** in a loop — the highest-volume paid path in the app), `useBackgroundReimagine.ts:134` (reimagine, `enhanceSketch`), and `StickerPicker.tsx:137` (generate a sticker from inside the editor). The Workshop (`workshopArt.ts` ×4, `WorkshopPage.tsx:521`) and Shelly chat (`useShellyChatFlows.ts:565`) generators are likewise uncapped but sit behind far less repeat-tapping. `settings/StickerLibraryTab`'s direct call is parent-only and deliberately uncapped. *Fix (a separate run — deliberately not widened into FEAT-166):* the wiring is now a known shape — a thin `useArtQuota` wrapper for the surface, `capReached` + `recordGeneration` handed down from the page, refuse before the spend, count only a real image, fail open. The per-page loop needs a decision FEAT-166's doors did not: whether an N-page illustrate-all counts N times (honest) or is refused whole at the cap (kinder), and what a mid-loop cap exhaustion should do.

- **UX-101 · P2 — FEAT-165's three capped doors `await` the courtesy counter, so an offline write can wedge the UI on art the kid already paid for (found by Codex on PR #1717, fixed there for the *fourth* door only).** `recordStickerArtGeneration` swallows a **rejection**, but nothing can bound a promise that never *settles* — and a Firestore write promise resolves only on server **ack**, so offline it stays pending indefinitely rather than failing. Every FEAT-165 door awaits it inside the `try`, ahead of a `finally` that clears the busy flag: `DrawingGroupCard.handleAddVersion` (`:148`, before `setPicking(false)` / `onChanged()`, with `finally { setBusy(false) }`) and `StickerLibraryTab.handleMakeVersion` (`:325`, before `setMakeVersionsOpen(false)`, with `finally { setMakingVersion(false) }`) both leave the dialog stuck on "Making…" forever, hiding a version that was generated and charged. `MakeStickerDialog.handleGenerate` (`:109`) is the mild case — `setGenerationPreview` already ran and the await is the callback's last statement — but it is the same shape. FEAT-166 hit this in its own copy and **fixed it there** (`SketchScanner.handleMakeFancy` now fires the counter with `void`, with a test that a never-settling write still reveals the image); the three merged doors were **deliberately not widened into** that run per its scope rail, so they are filed here. *Fix:* the same one-word change (`await` → `void`) in all three — failing open has to mean the art never waits on the counter, not merely that a *thrown* counter is ignored. Cheap, mechanical, and worth doing in one pass with UX-100.
